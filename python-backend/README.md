# Python helper (local development prototype)

This local service uses only Python's standard library, so no pip install is required. It includes a deterministic mock-provider gateway for practicing typed contracts before adding a real AI provider, plus read-only project summary and search.

## Endpoints

- GET /health reports service status, the Python version, and ai_connected=false.
- POST /echo accepts a small JSON message and returns it from Python to verify the TypeScript-to-Python bridge.
- POST /chat validates a chat request and returns a deterministic mock response with provider, model and ai_connected metadata.
- GET /workspace/summary counts eligible code/text files under this repository and returns a few relative sample paths.
- GET /workspace/search?q=term performs case-insensitive literal search and returns bounded file/line/snippet results.

The service binds to 127.0.0.1 only. Project search is read-only, scoped to the repository containing this service, and skips common generated/dependency folders, environment files, credentials, key files, symlinks and oversized files. It does not persist an index, call an external AI model, run shell commands, or send project contents to a model/provider. This is deterministic line-based search, not semantic search and not an AI feature.

## Run it on Windows

Open a separate PowerShell 7 terminal:

    cd C:\Projects\DIS-AI-Dev
    py -3 .\python-backend\server.py

Keep this terminal open while using the desktop app. Stop it with Ctrl+C.

## Run automated tests

    cd C:\Projects\DIS-AI-Dev
    py -3 -m unittest discover -s .\python-backend -p "test_*.py" -v

## Test the mock chat endpoint manually

With the service running:

    Invoke-RestMethod -Uri "http://127.0.0.1:8765/chat" -Method Post -ContentType "application/json" -Body '{"message":"Explain the project roadmap"}'

The response will identify provider=mock, model=dis-ai-dev-mock-v1, and ai_connected=False. The reply is deterministic and is not generated by an AI model.

## Manual examples

With the service running, use another PowerShell window:

    Invoke-RestMethod -Uri "http://127.0.0.1:8765/health"
    Invoke-RestMethod -Uri "http://127.0.0.1:8765/workspace/summary"
    Invoke-RestMethod -Uri "http://127.0.0.1:8765/workspace/search?q=PythonHelperHandler"

Search text must contain 2–100 characters. Results are limited to 30 snippets; individual files larger than 256 KiB are skipped. This is a simple line-based search, not semantic/vector search.

## Beginner notes

- ThreadingHTTPServer handles requests using Python's standard library.
- GET /health checks whether the service is reachable.
- GET /workspace/summary and GET /workspace/search return read-only local results; query parameters pass the search term.
- POST /echo receives JSON data in the request body.
- POST /chat validates an untrusted request and calls the replaceable ChatProvider interface.
- MockChatProvider provides deterministic replies so tests do not depend on API keys, internet access or paid model usage.
- JSON lets TypeScript and Python exchange structured data.
- 127.0.0.1 is this computer's loopback address.
- unittest runs repeatable checks without installing another test package.
